# 枚举值接地（Column Value Grounding）

## 为什么需要

真实业务评测暴露出一个稳定失败模式：用户说"已支付的金额"，模型生成
`WHERE status = :status` 并绑定 `'已支付'`，而库里存的是 `paid`，查询返回空结果。
这不是 SQL 写错，是**业务词没有接地到库内枚举值**。

2026-11-08 的 40 条评测里，`BIZ-008`、`BIZ-010`、`BIZ-036` 三条都是这个问题，占失败数的四分之一。

## 怎么做的

1. 管理员在数据源配置里显式列出可接地的列（`data/datasources.json`）：

```json
{
  "id": "mysql-main",
  "backend": "mysql",
  "allowed_tables": ["enterprise_orders", "payments", "..."],
  "value_columns": ["enterprise_orders.status", "payments.status", "payments.method", "products.category"],
  "roles": ["admin", "analyst"]
}
```

2. 查询进入生成阶段前，对配置列执行受限采样：

```sql
SELECT DISTINCT `table`.`column` FROM `table` WHERE `table`.`column` IS NOT NULL LIMIT 16
```

3. 采样结果以 `column_values` 放进模型上下文，模型能直接看到 `status ∈ {completed, pending, cancelled}`，
   于是绑定 `paid` 而不是 `已支付`。

## 安全边界

- **只采配置列**：不做全表自动枚举，列清单由管理员维护；
- **只采授权表**：表必须在当前调用者通过 `filter_schema` 过滤后的 schema 中，否则跳过；
- **标识符校验**：表名、列名必须匹配 `^[A-Za-z_][A-Za-z0-9_]{0,63}$`，用反引号包裹后再拼接；
- **有界**：最多 12 列、每列 16 个值、单值 64 字符，按数据源缓存 300 秒；
- **失败降级**：采样异常返回空上下文，绝不让查询失败；
- **不要在行级授权列上配置**：当前实现只做表级授权过滤，行级 scope 列（如按区域授权的 `region`）
  若被配置，采样结果可能越过行范围。这是已知限制，配置时应避开。

## 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `VALUE_GROUNDING_ENABLED` | `true` | 总开关；关闭后完全不采样 |
| `VALUE_GROUNDING_MAX_COLUMNS` | `12` | 单次最多接地的列数 |
| `VALUE_GROUNDING_MAX_VALUES` | `16` | 每列最多返回值数 |
| `VALUE_GROUNDING_MAX_VALUE_CHARS` | `64` | 单值最大字符数 |
| `VALUE_GROUNDING_TTL_SECONDS` | `300` | 采样缓存有效期 |

数据源没有 `value_columns` 时该功能不生效，也不产生任何额外查询。

## 效果（2026-11-08，40 条真实库评测，配对实验）

| 配置 | 运行 1 | 运行 2 | 运行 3 | 中位数 |
|---|---|---|---|---|
| 关闭接地 | 72.5% | 75.0% | 72.5% | 72.5% |
| 开启接地（12 列，含区域） | 75.0% | 77.5% | 75.0% | 75.0% |
| 开启接地（9 列，去掉区域） | **80.0%** | **80.0%** | **80.0%** | **80.0%** |

- 净增 **+7.5 个百分点**（29/40 → 32/40），三次运行完全一致。
- 直接修好的用例：`BIZ-008`、`BIZ-010`、`BIZ-036`（全部是参数值未接地）；`E_EMPTY_RESULT` 从 1–2 降为 0。
- 第一版把 `region` 等中文地域列也纳入接地，导致 `BIZ-027`（评分最高 5 家供应商）稳定回退——
  模型因此多选了列。去掉非必要列后回退消失，说明**接地清单要窄**。

## 边界与不宣称

- 只实现 MySQL 采样；SQLite、PostgreSQL 和实验连接器返回空上下文，需要时再逐个实现。
- 不做自动列发现：需要人工判断哪些列是枚举列，避免把自由文本、敏感列或行级授权列喂给模型。
- 这 7.5 个百分点只代表这 40 条合成业务问题上、当前 DeepSeek 与这套配置的结果，
  不等于企业真实业务准确率。
- 剩余失败集中在"多返回描述列"（3 条）、"月份表示差异"（2 条）、"口径偏差"（2 条）和
  "不支持的相关子查询"（1 条），与接地无关。
