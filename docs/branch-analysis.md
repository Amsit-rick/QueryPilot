# 分析分支

分析分支允许用户从一个已完成的历史轮次创建新的独立 `DataTask`，用于验证不同筛选条件、指标口径或业务假设。分支不会覆盖来源任务的状态、步骤、审批或结果资产。

## 使用流程

1. 在工作台恢复一个已完成任务。
2. 在目标历史轮次下选择“从此轮创建分析分支”。
3. 输入新的分析假设并提交。
4. 系统创建独立任务，重新执行权限、Schema、SQL 安全、成本、审批和审计链路。
5. 在“假设对比”中切换主任务和各分支；比较区只显示问题、答案摘要、状态、行数和字段数。

分支任务支持继续多轮追问，也支持在深度限制内继续创建嵌套分支。返回来源任务不会修改当前分支的任何数据。

## 请求契约

创建分支仍使用 `POST /api/v1/query` 或版本化流式查询入口：

```json
{
  "question": "假设只看华东区域",
  "branch_from_task_id": "来源任务 ID",
  "branch_from_trace_id": "来源轮次 trace ID",
  "branch_label": "华东假设",
  "client_request_id": "客户端幂等 ID"
}
```

分支请求不能与 `task_id` 或 `follow_up` 同时使用。数据源由来源任务锁定，客户端不能把分支切换到其他数据源。

响应和 `GET /api/v1/tasks/{task_id}/conversation` 会返回：

```json
{
  "branch_origin": {
    "parent_task_id": "直接来源任务 ID",
    "root_task_id": "分支族根任务 ID",
    "source_trace_id": "来源轮次 trace ID",
    "label": "华东假设",
    "depth": 1
  }
}
```

`GET /api/v1/tasks/{task_id}/branches` 返回当前账号可访问的整个分支族安全摘要。该接口不返回 SQL、绑定参数或结果行。

## 上下文与安全边界

- 来源任务必须属于当前租户和账号，且状态为 `completed`。
- 来源轮次必须是已完成的查询步骤；失败、审批中或不存在的轮次会被拒绝。
- 初始 Prompt 只继承选定轮次及之前的安全上下文，不会带入来源任务的后续轮次。
- 历史 Schema 会按当前账号权限重新过滤；撤权表和字段不会因分支继承重新出现。
- 结果行、绑定参数、原始 SQL、模型原始解释和失败 SQL 不进入分支 Prompt。
- 来源任务只新增 `task_branch_spawned` 审计事件；分支任务记录独立的 `task_branch_created`、步骤、审批和结果资产。
- 前端使用普通文本插值展示标签和答案摘要，不渲染用户提供的 HTML。

## 限制配置

```dotenv
ANALYSIS_BRANCH_MAX_DEPTH=3
ANALYSIS_BRANCH_MAX_CHILDREN=20
```

深度限制防止无限嵌套，子分支数量限制控制单个任务的扇出。修改阈值前应结合任务列表、数据库索引、审计容量和 UI 可读性进行容量评估。

## 当前边界

当前能力已通过本地内存仓储、MySQL 迁移、API、前端 E2E 和 390px 布局验证，但未进行多机并发、超大分支族、真实企业权限变更过程或生产容量验收。分支比较是安全摘要，不是自动统计显著性分析或业务结论裁决。
