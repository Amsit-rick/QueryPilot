# 每轮 Token 与人民币成本回执

## 目标

每次查询回答后展示本轮输入、输出、总 Token 和人民币估算，并在任务刷新、恢复和多轮对话后保持一致。

## 计量口径

- `provider`：Token 数量来自模型供应商响应。
- `estimate`：供应商未返回用量时，使用本地保守估算。
- `none`：显式 SQL、本地 SQL 计划缓存命中或其他未调用模型的路径。
- 人民币金额始终为“约”，按 `.env` 中可配置的缓存命中输入、缓存未命中输入和输出单价计算，不作为供应商账单。
- 供应商未提供完整缓存明细时，未归类输入按缓存未命中计费，避免低估。

## TDD 证据

首轮测试因缺少 `build_usage_summary` 在收集阶段失败。实现后覆盖：

1. DeepSeek/OpenAI 兼容响应的输入、输出及缓存 Token 解析。
2. LangChain `usage_metadata` 与 `response_metadata.token_usage` 解析。
3. 供应商实测、系统估算、未调用模型三种状态。
4. 人民币分项计价、非法负值归零及缓存明细缺失的保守计费。
5. 查询响应、Table Artifact 和 `/conversation` 恢复链路一致。
6. 前端回答下方展示和历史任务兼容。

- 真实 MySQL 多轮追问：输入 `859`、输出 `54`、总计 `913 Token`、约 `¥0.00139736`，口径为“供应商实测”；浏览器强制刷新后仍保持相同数值。

## 边界

- 人民币价格配置需要随供应商价格变化人工更新。
- 供应商 Token 为真实计量时，人民币仍是本地折算值。
- 旧任务没有历史 usage 元数据，界面显示“历史任务未记录 Token 用量”，不会反推或伪造用量。
